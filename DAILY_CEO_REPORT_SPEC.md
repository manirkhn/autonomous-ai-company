## 1. Executive Summary & Objective

The Daily CEO Progress Report transforms the human owner's device from the runtime of the company into an executive monitoring terminal. The company operates 24/7 in the cloud with zero requirement for the owner's laptop to stay awake, open, or connected.

Every evening at **23:00 Dubai time**, the system deterministically compiles all verified facts across the enterprise, validates them through an automated **Section 34 Truth Check**, optionally formats a high-integrity synthesis via Google Gemini, and delivers the finalized brief to `manirkhn@gmail.com`.

## 3. Data Sources & Deterministic Math

Under our zero-hallucination governance model, **no financial, operational, or activity numbers are generated by language models**. All metrics originate from deterministic database queries:

```
SQLite Ground Truth Ledger (data/company.db)
├── revenue_ledger ──> Verified Revenue ($29.00), Pending ($0.00), Refunds ($0.00)
├── financial_transactions ──> Verified Expenses ($0.00)
├── tasks ──> Completed, In Progress, Blocked, Failed counts
├── employees ──> Active agent roster count (12+ specialized agents)
├── employee_activities ──> Audit-grounded task context, project, experiment
├── approvals ──> Pending owner action items (0 or N)
└── experiments ──> Active revenue experiments (EXP-P4-1790269597)
```

### Truth Invariants:
1. `Verified Profit = Verified Revenue - Verified Expenses` ($29.00 - $0.00 = $29.00).
2. Only `payment_status = 'VERIFIED'` transactions with processor receipt evidence count as company revenue.
3. Virtual treasury numbers are never conflated with verified cash.

## 4. Section 34 Automated Truth Check Validation

Before any email is queued or dispatched, the system runs an automated pre-flight assertion:

```python
is_valid, errors = DailyCEOReportGenerator.validate_truth_check(facts)
```

| Check Item | Validation Rule | Action on Failure |
| :--- | :--- | :--- |
| **Revenue Check** | `report.revenue == ledger.verified_revenue` | Abort transmission; mark report `FAILED` |
| **Profit Check** | `report.profit == (report.revenue - report.expenses)` | Abort transmission; mark report `FAILED` |
| **Customer Check** | `report.customers == db.verified_customers` | Abort transmission; mark report `FAILED` |
| **Task Count Check** | `report.tasks == db.task_records` | Abort transmission; mark report `FAILED` |
| **Approvals Check** | `report.approvals == db.pending_approvals` | Abort transmission; mark report `FAILED` |

If validation fails, the email is **NOT** sent. An error entry is recorded in `ceo_reports` with status `VALIDATION_FAILED`, and an alert is displayed on the dashboard.

## 5. Google Gemini Provider Integration

Google Gemini is integrated via the `LLMProvider` abstraction (`providers/llm.py`):

1. **Role of Gemini:** Synthesizes the structured fact dictionary into an executive narrative. Gemini is provided only verified numbers and instructed never to invent data.
2. **Safe Fallback:** If Gemini API is unreachable, quota-limited, or network-blocked, the system falls back seamlessly to `DeterministicFallbackProvider` within 2.5 seconds.
3. **No Downtime:** The company never crashes or stops due to third-party LLM latency.
4. **Credential Security:** API keys are read from `GEMINI_API_KEY` environment variables. No secrets are committed to Git, logged to disk, or exposed to the frontend.

## 6. Email Delivery Pipeline & Security

**Recipient:** Strictly `manirkhn@gmail.com`.  
**Subject:** `🏢 AI Company — Daily CEO Progress Report — {DATE}`  

### Delivery Rails:
1. **SMTP Transport:** Active when `SMTP_HOST`, `SMTP_USER`, and `SMTP_PASSWORD` are supplied. Connects via STARTTLS with a 10s connection timeout.
2. **Local Secure Outbox Fallback:** When external credentials are not yet supplied, reports are saved to `data/outbox/{report_id}-{delivery_id}.json` with status `QUEUED_LOCAL_OUTBOX`. This guarantees zero lost reports during initial bootstrap.
3. **Password Protection Invariant:** The owner's Google password is never requested, stored, or processed.

## 8. Report Retention & Archiving

Every report is permanently archived in two formats inside `reports/daily/`:
- `reports/daily/YYYY-MM-DD-ceo-report.md`
- `reports/daily/YYYY-MM-DD-ceo-report.json`

Previous reports are **never overwritten**. If multiple reports are generated on the same date, a collision-resistant timestamp suffix is appended.
